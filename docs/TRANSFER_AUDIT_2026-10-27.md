## 2. Повторная проверка бюджета: расхождение объяснено (27.10.2026)

**Исправление ошибочного вывода первого аудита.** Пять функциональных категорий расходов НЕ включают проценты по государственному долгу. Платежи по процентам входят в `fiscal_spending_total_billion` отдельным расчётным слагаемым:

`fiscal_spending_total_billion ≈ fiscal_spend_social_billion + fiscal_spend_economy_billion + fiscal_spend_defense_billion + fiscal_spend_admin_billion + fiscal_spend_other_billion + fiscal_debt_total_billion × fiscal_interest_rate_pct / 100`.

Для США: сумма пяти направлений = `665.84739508` млрд G$; совокупный долг = `2016.7148` млрд G$; ставка обслуживания = `2.6%`; проценты = `52.4345848` млрд G$; вместе = `718.28197988` млрд G$, что с округлением равно заявленным `718.28198`.

Для **всех 12 стран** подтверждено, что кажущееся расхождение точно совпадает с `debt_total × rate / 100` в пределах округления (остаток меньше `0.000001` млрд G$ у каждой). Следовательно, **бюджетная арифметика согласована, отсутствующей неопределённой статьи нет и исправлять стартовые JSON, HEAD либо манифест не требуется**. Предыдущее утверждение о «необъяснённой разнице» недействительно. Пять функциональных категорий — не полный перечень совокупных расходов без обслуживания долга.

Текущий `scripts/verify_release.py` отдельно не тестирует это шестое слагаемое. Для последующих релизов полезно добавить проверку, но само отсутствие теста не доказывает ошибку данных. Показатель процентов — **игровая модель**, а не проверенный график реальных исторических выплат по каждому долгу.

**Версии:** `HEAD.rules_version=RC0.8` — основной общий регламент; `RC0.10` — утверждённая стартовая военная ведомость и оценка техники в `countries/*.json`. Эти версии сосуществуют, нельзя автоматически переименовывать общий `HEAD.rules_version` в RC0.10 без отдельного утверждения новой редакции правил.
